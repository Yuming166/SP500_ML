## TL;DR

9月2日单日完成了 **Recovery V3.2 → V3.3 → V3.4.1 → V3.5 (PACE 协议)** 的完整迭代，配合已冻结的 Pilot-LLM V12.1 (BoolQ PASS)，形成了一个**"检测 → 修复 → 跨域压力测试 → 失败后的协议再冻结"** 的方法学闭环。本文档：

1. 总结当前所有冻结结果的正负证据
2. 评估 ACL/NAACL 投稿范围内的原创性边界
3. 按紧迫度给出 NAACL 截稿前的方向建议

**核心叙事（适合 NAACL 投稿 abstract）：** 让环境持有 provenance 而非模型暴露私有 reasoning → 配对干预（remove/reverse/substitute）制造可观察的行动依赖 → 预冻结的 pre-outcome 风险契约 R_PI → 在 BoolQ 358 题 disjoint 复制上 AUROC 0.705 [0.620, 0.781] 击败 chance → 用 V3.3 CEW 在 AVeriTeC 上完成"修复"半边 → 用 V3.4.1 PBWJ 失败定义迁移边界。

## 2. 原创性评估

### 2.1 真正新的是什么

1. **"让环境持有 provenance，让模型暴露干预反应"** 的方法学切割（参见 `docs/asof_provenance_faithfulness.md` 第 21-49 行）。
   - 与 Chain-of-Thought faithfulness（拷问 CoT）和 explanation faithfulness（看模型解释）不同，拷问的是 **answer ↔ environment-supplied evidence** 的可干预依赖。
   - 与 Chen et al. 2024 *"Interventions" in LLM evaluation* 方向相关，但 paired complete potential outcomes（每个例子都对 KEEP/0/1/both 做全配对）在 LLM 文献里属于稀缺做法。

2. **Pre-outcome risk contract with explicit outcome leakage audit**（参见 `paper/acl_draft.md` §6.1）。
   - R_PI 只接受 3 个字段；regression test poison outcome 字段后必须 bit-identical。
   - V10.4 leakage 的事后审计是 "methodology paper" 的卖点。

3. **冻结协议 + preregistration + 多 stage 演化叙事**（参见 `docs/work_log_4.md`、`docs/work_log_5.md`）。
   - 这是真正的 ML 论文里少见的工程化做法。

### 2.2 不太新的部分

- "Multi-agent debate 能被 shared evidence 骗" 本身已经有很多人写过（Michael et al. 2023 conformity, Khan et al. 2024 sycophancy）。贡献是 **检测和修复** 这件事，而不是发现它。
- "Selective prediction + abstention" 在 conformal LLM routing 里有先例。
- "Stance TF-IDF + jury" 是 NLP 经典做法，不是新意；新意在怎么冻结、怎么 gate。

### 2.3 原创性总体判断

**ACL/NAACL 范围内的真实新意是"方法组合 + 协议严谨性"，不是某个单一组件**。这是个 *methodology / empirical rigor* 类的贡献，不是 *new architecture* 类的贡献。NAACL 接收这类工作，但需要：

- 至少 1 个干净的正结果（✓ BoolQ V12.1 有，但被 label 反转打折）
- 至少 1 个有意义的负迁移故事（✓ PBWJ 有，但被审稿人解读为"weakness"还是"boundary"取决于 framing）
- 至少 1 个跨模型/跨域的最小验证（✗ **目前缺**）

## 3. NAACL 投稿方向建议（按紧迫度排序）

### 🔴 紧迫（1-2 周内必须决策）

**1. 切范围：BoolQ V12.1 PASS 做主轴，Recovery 降为 supplementary。**
理由：NAACL 截稿通常在 10-11 月（假设 NAACL 2027 在 2027 年中）。一篇 8 页论文塞不下：
- Pilot-LLM V4/V5 + Recovery V2.2/V3.3/V3.4.1 + BoolQ V12.1 + AMIR + 财务 replay

建议主论文框架：

```
Title: When Consensus Lies: Pre-Outcome Risk from Paired Evidence Interventions

1. Introduction — false consensus 在 multi-agent 系统的具体失败模式
2. Protocol — environment-held provenance, paired remove/reverse/substitute
3. Pre-outcome risk — R_PI + leakage audit
4. BoolQ V10.4 (invalidate leakage) + V11.1 (underpowered) + V12.1 (PASS)
5. Cross-domain stress — AMIR + S&P 500 replay（明确标注 exploratory）
6. Limitations — single model, label asymmetry, etc.
```

把 Recovery V3.3 CEW + V3.4.1 PBWJ 作为 **附录 / supplementary**，这样：
- 主线故事清晰：检测 → abstention
- Recovery 的故事作为"配套修复方向"留给 follow-up
- 负迁移被重新 framing 为"boundary of the method"

**2. 至少引入 1 个第二模型家族。**
- 当前最大的 generalization gap 就是 single-model Qwen3.5-4B（论文 §8 第一条已经承认）。
- 即便是小规模（100-200 题），Llama-3.1-8B-Instruct 或 Mistral-7B-Instruct 跑一遍 V12.1 协议就能堵住这个洞。
- 如果当前 `http://10.63.0.82:31518/v1/chat/completions` 跑不了，请部署一个小的（sglang + 4-bit 量化 + 单 GPU 足够 7B/8B）。

**3. 处理 BoolQ 的 label heterogeneity。**
- 这不是可以"摆在那里"的问题——审稿人会问"method 只是学会了 yes 比 no 更长？"
- 至少做 **label-conditional ablation**：在 yes/no 子组内分别重拟合 R_PI 的 simplex 权重，看 label 是结构性问题还是权重问题。
- 或者做 **label-stratified bootstrap**，确认 aggregate AUROC 不只是 yes 群驱动的假象。

### 🟡 重要（2-4 周内）

**4. R_PI 权重的 post-hoc 问题。**
- §5.3 诚实承认 F_shared 单坐标 AUROC 0.498（在 chance 附近），但公式给了 0.6 权重。
- 这意味着 R_PI 的"成功"主要靠 I_flip（0.807），而 0.6 权重在拖后腿。
- 三个选择：
  - (a) 维持 frozen 的 0.1/0.3/0.6 → 必须承认是 historical lock
  - (b) 重新冻结一个 **只用 2 个有效坐标** 的版本（0.0/0.5/0.5），在新 protocol 下跑 → 这是新方法，不是 post-hoc tuning
  - (c) 在 supplementary 里跑一个"re-fit" ablation，展示如果只保留 I_flip 会怎样
- 推荐 (b)，但作为 V13/V14 而不是改 V12.1。

**5. 写好 Related Work 的 agent-routing/conformal routing 段。**
- Conformal LLM routing (Angelopoulos et al. 2024)、FrugalGPT (Chen et al. 2024)、RouteLLM (Ong et al. 2024)、AgentAuditor (Motwani et al. 2024) 都需要明确 cite + 区分。
- Decision-Aware Memory Cards 是最接近的工作——审稿人会问"你和它差在哪"。

**6. 财务 replay 的 framing。**
- 现在论文说 "exploratory"，"informative but not the main claim"。这是对的，但需要在 §6.4 把 "ranking good, calibration bad" 的解读做得更扎实。
- V4/V5 AMIR 的 AURC delta CI 跨 0（AURC delta -0.0078 [-0.0607, 0.0459]），这意味着 *市场 replay 的 primary endpoint 没通过*。这是 honest 但要明确写出，不要藏在表格里。

### 🟢 长期（决定项目走向）

**7. 关于 V3.5 PACE。**
- 9月2日协议刚冻结，还没跑。如果能在 2-3 周内跑完 PACE（600 + 500 examples @ 5 agents × 3 actions ≈ 8,000 calls），并且结果 PASS，那 V3.3+PACE 能组成一个完整的 "detect → repair" 两阶段故事，可以作为 **NAACL submission 的核心方法**。
- 如果跑出来又 NEGATIVE（参照 V3.4.1），那更坚定地按上面 (1) 的方案切范围。

**8. 思考长期研究方向。**
- 当前研究问题"consensus ceases to be evidence"是一个 **方法论问题**，不是一个新算法问题。
- 如果要做"更好的"工作，下一步可以考虑：
  - **Time-of-decision 信息含量**：为什么 paired intervention 在某些 label 群有效？是否和 evidence polarity asymmetry 有关？
  - **Stance calibration 的元学习**：能不能训练一个 model 来预测 "this domain's stance scores need re-calibration by X"？这能解决 PBWJ 失败的核心问题。
  - **Audit-as-tool**：把这个 protocol 卖给 LLM providers，让他们自检？这个角度更 NAACL 主会喜欢。
